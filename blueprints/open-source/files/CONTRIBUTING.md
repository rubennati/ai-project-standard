# Contributing

Thank you for contributing to {{PROJECT_NAME}}.

## Workflow

1. Create a short-lived branch from `main`.
2. Keep pull requests focused and easy to review.
3. Link the related issue where there is one.
4. Request review before merge.

Branch names: `feature/*`, `fix/*`, `docs/*`, `refactor/*`.

## Expectations

- No direct commits to `main`
- Prefer incremental changes
- Update documentation in the same pull request as the change

## Inbound rights

Contributions are accepted under the project's licence. Sign off each commit
with `git commit -s` to certify you have the right to contribute it — see the
[Developer Certificate of Origin](https://developercertificate.org/).

Pick one inbound-rights mechanism and keep it. Do not run a DCO and a
contributor licence agreement side by side.

## Checklist

- Problem and scope are described
- Documentation updated where needed
- CI passes
