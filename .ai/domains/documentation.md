# Documentation

Documentation is the product here, so its rules are not stylistic.

- **State it once**, in the place a reader looks first, and point at it from
  everywhere else. Duplication drifts.
- **A claim about the outside world carries a source and a check date.** CI
  enforces this for `docs/`; the same discipline is what the website runs on.
  Vendor behaviour changes without announcement.
- **Say what is true rather than what sounds finished.** Sections still being
  worked on say so instead of shipping filler.
- Documentation lands in the same pull request as the change it describes.
- Prefer a table over three paragraphs, and a worked example over a description.
- Delete what stopped being true. Stale documentation is worse than none,
  because it is trusted.
- English throughout, per `docs/language-style.md`. The website's translated
  pages are the only exception in the project.
